# TRS-OS Boot Volume Mounting Error Analysis

## Symptom

When launching `TRSDOS.bin` built by the `Makefile` on the Agon platform via Shawn Sijnstra's `OSboot` loader (e.g. inside `fab-agon-emulator` or on physical Agon hardware), initialization halts at the boot splash with the following error:

```text
WELCOME to TRSDOS 7
------------------------------------------------------------
Copyright 2009 - 2024 Daniel Paul Martin. All rights reserved.
Preloaded LSDOS 6.3.1 Copyright Roy Soltoff. All rights reserved.
BASCOM Copyright 1984 Microsoft Inc. All rights reserved.
Free to distribute & use this program provided above copyright
is preserved & displayed. All rights reserved.
text filled @ipl
System stack set.
System clock set.
Memory management initialized.
Machine hardware flag set.
CPU initializization completed.
BIOS ready.
Please wait.....

>--------------------------------------------<
|                   ERROR                    |
|            mounting BOOT volume.           |
>--------------------------------------------<
```

The system hangs indefinitely in an infinite loop (`jr $`) and fails to reach the interactive IPL menu or the TRSDOS command prompt.

---

## Root Cause

The `TRSDOS.bin` file generated by `make` is **only the operating system kernel and slice descriptor tables** (66,048 bytes). It is missing the **in-memory boot disk image (Drive `:0` / Volume 0)** required by the BIOS IPL sequence.

### 1. Code Trace in `TRSDOS_7` Sources

During the BIOS initialization in [`TRSDOS_7/SYS0_IPL/ipl-BIOS.s`](TRSDOS_7/SYS0_IPL/ipl-BIOS.s#L44-L103):

1. **Slice 0 Read (`0x010000`)**:
   TRS-OS reads the 256-byte slice descriptor at `0x010000` (defined in [`SYSRES/memory/memory_slice0.s`](TRSDOS_7/SYSRES/memory/memory_slice0.s)), which points to Slice 1 at address `0x010100`.
2. **Slice 1 Read (`0x010100`)**:
   TRS-OS reads the volume offset table at `0x010100` (defined in [`SYSRES/memory/memory_slice1.s`](TRSDOS_7/SYSRES/memory/memory_slice1.s)). The first entry in Slice 1 specifies the offset from Slice 1 to Volume 0 (the root boot disk, Drive `:0`):
   ```z80
   db  00h, 01h, 00h, 00h  ; Offset to volume 0 (drive 0)
   ```
   Adding offset `+0x0100` to the base address of Slice 1 (`0x010100`) calculates the physical memory address for Volume 0:
   $$\text{Volume 0 Address} = 0x010100 + 0x000100 = 0x010200$$
3. **Magic Signature Check**:
   At lines 81–103 of [`ipl-BIOS.s`](TRSDOS_7/SYS0_IPL/ipl-BIOS.s#L81-L103), the BIOS copies the first 256 bytes from `0x010200` into `volbuf` and compares the first 8 bytes against the Misosys DiskDISK ASCII signature `"DiskDISK"`:
   ```z80
   		ld	bc,8				; Test a string length of 8 characters.
   		ld	hl,string1$			; Get pointer to string containing 'DiskDISK'
   		ld	de,volbuf			; Address of buffer to test.
   tstmore0	ld	a,(de)				; Get char pointed to by DE.
   		inc	de				; Bump to next char.
   		cpi					; Test and increment HL & DE while decrementing BC (char count).
   		jp	nz,mounterr0			; If they dont match we can stop now.
   ```
4. **Error Vector**:
   If `"DiskDISK"` is not found, the code jumps to `mounterr0` in [`TRSDOS_7/SYS0_IPL/ipl-subroutines.s`](TRSDOS_7/SYS0_IPL/ipl-subroutines.s#L74-L75):
   ```z80
   mounterr0	PUMP	DEVICE.console,mounterrmsg0
   		jr	$				; If no root volume we cannot boot.
   ```
   This renders [`mounterrmsg0`](TRSDOS_7/SYS0_IPL/screens/ipl_error_screen.s#L9-L14) (`"ERROR mounting BOOT volume."`) to the console and halts the CPU.

---

### 2. Binary Generation Gap in `Makefile`

* In [`TRSDOS_7/TRSDOS.s`](TRSDOS_7/TRSDOS.s#L170-L177), the assembly source tree ends immediately after including `memory_slice0.s` and `memory_slice1.s`:
  ```z80
  ; Memory >64K starting @010000h

  		include "memory_slice0.s"                       ; Container for slice 0 data.
  		include "memory_slice1.s"                       ; Container for slice 1 data.

  		include 'equates-check.s'

  		END       trs_os
  ```
  The highest assembled address in `TRSDOS.hex` is `0x0101FF`.
* Rule `5b` of the `Makefile` converts `TRSDOS.hex` to flat binary using `hex2bin`:
  ```makefile
  $(TARGET_BIN): $(TARGET_HEX)
  	$(HEX2BIN) -s 000000 -p 00 "$<"
  ```
  This creates a `TRSDOS.bin` that is exactly **66,048 bytes** (`0x10200` bytes).
* Because the binary ends at `0x0101FF`, **no data is populated at `0x010200`**. When loaded into RAM, memory from `0x010200` onwards consists of uninitialized emulator memory or zeros, failing the `"DiskDISK"` signature check.

---

### 3. How `OSboot` Boots TRS-OS

Shawn Sijnstra's `OSboot.bin` loader operates as follows:

* **Monolithic Image Loading**:
  `OSboot` does not construct or format in-memory filesystems at boot. Instead, it reads up to **496 KB** (`0x03C000` + `0x040000` bytes) from the specified binary file (`TRSDOS.bin`) and loads it into Agon SRAM starting at address `0x000000`.
* **Expected Binary Layout**:
  Pre-packaged distribution binaries (such as `TRS-OS_Squirrel.bin` from `TRS-NET.zip`) are **491,520 bytes** (480 KB):
  
  | Memory Address Range | Size | Description |
  | :--- | :--- | :--- |
  | `0x000000` – `0x00FFFF` | 64 KB | TRS-OS kernel, SVC handlers, device drivers, lowcore |
  | `0x010000` – `0x0100FF` | 256 B | Slice 0 table (pointer to Slice 1) |
  | `0x010100` – `0x0101FF` | 256 B | Slice 1 table (pointer to Volume 0 at `+0x0100`) |
  | `0x010200` – `0x077FFF` | 425,472 B (~415.5 KB) | Volume 0: Pre-formatted LS-DOS 6.3.1 Misosys `DiskDISK` image |

* **The `[diskfile]` Argument in `OSboot`**:
  `OSboot` accepts an optional second file argument:
  ```text
  OSboot [-Xvf] <binaryfile> [diskfile]
  ```
  This optional parameter mounts a disk image as **Drive `:1`** (loaded at `0x45300` / `0x0EE300`), **not Drive `:0`**. Drive `:0` is always expected to be bundled directly inside `<binaryfile>`.

---

## Solution

To create a working, bootable binary for `OSboot`, the 425,472-byte `DiskDISK` boot volume must be appended to the 66,048-byte compiled `TRSDOS.bin` at offset `0x010200`.

### Manual Fix

1. Extract the boot disk image from `TRS-OS_Squirrel.bin` (found in `TRS-NET.zip`):
   ```python
   # extract_boot_volume.py
   with open("TRS-OS_Squirrel.bin", "rb") as f:
       f.seek(66048)  # Seek past 0x010200
       disk_data = f.read()

   with open("TRSDOS_7/boot_volume.dsk", "wb") as f:
       f.write(disk_data)
   ```

2. Concatenate the compiled kernel with the extracted boot volume:
   ```bash
   cat TRSDOS_7/TRSDOS.bin TRSDOS_7/boot_volume.dsk > ../fab-agon-emulator-v1.2.4-macos-arm64/sdcard/TRSDOS.bin
   ```

3. Verify the combined file size:
   ```bash
   ls -l ../fab-agon-emulator-v1.2.4-macos-arm64/sdcard/TRSDOS.bin
   # Should be exactly 491,520 bytes
   ```

### Recommended `Makefile` Update

In `Makefile`, target `$(TARGET_BIN)` can be updated to automatically package the boot volume:

```makefile
BOOT_DSK     := $(SRC_DIR)/boot_volume.dsk
TARGET_STAGE := $(SRC_DIR)/TRSDOS_kernel.bin

$(TARGET_BIN): $(TARGET_HEX) $(BOOT_DSK)
	@echo "==> Generating flat kernel binary from $(TARGET_HEX)..."
	$(HEX2BIN) -s 000000 -p 00 "$<"
	@mv -f "$@" "$(TARGET_STAGE)"
	@echo "==> Bundling kernel with boot volume into $(TARGET_BIN)..."
	cat "$(TARGET_STAGE)" "$(BOOT_DSK)" > "$@"
	@echo "==> Build successful: $(TARGET_BIN) ($$(wc -c < $(TARGET_BIN) | tr -d ' ') bytes) ready for OSboot."
```
